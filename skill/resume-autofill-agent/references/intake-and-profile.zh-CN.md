# 信息采集与档案协议

## 首次启用

按以下顺序搜索：

1. 当前请求中的附件；
2. 当前工作区内的简历、个人档案、成绩单、证书、作品和网申文件；
3. 获准使用的本地长期档案或记忆索引；
4. 用户明确授权的只读连接来源，例如 GitHub。

找到可用简历或档案后立即开始，只询问阻塞信息。完全没有可用来源时，再请求一份简历，或请求最小化的身份、教育与经历摘要。不得在检查现有材料之前强制用户填写固定问卷。

## 档案模块

在材料支持时维护以下模块：

- 身份与联系方式；
- 求职或申请偏好；
- 教育与成绩单；
- 实习与工作经历；
- 项目、科研、出版和作品附件；
- 代码仓库与公开链接；
- 奖项、证书、技能与语言；
- 校园活动、兴趣及岗位定制素材；
- 仅在表单明确要求时记录家庭或亲属声明；
- 冲突、占位规则、待确认问题与隐私说明。

## 来源账本

为重要字段保留类似记录：

```json
{
  "field": "education[0].end_date",
  "value": "<YYYY-MM>",
  "source": "<当前简历文件名>",
  "source_date": "<YYYY-MM-DD 或 unknown>",
  "confidence": "high",
  "priority": 3,
  "status": "verified",
  "notes": "<可选说明>"
}
```

可使用 `verified`、`user_confirmed`、`conflicting`、`unknown` 和 `application_placeholder`。占位记录必须写明具体规则和适用的网申。

## 自适应提问

仅在以下情况提问：

- 必填字段没有可靠值；
- 两个高优先级来源相互冲突；
- 字段敏感，或属于法律/诚信声明；
- 改写会实质性改变责任范围；
- 下一步将提交、签署、授权或产生外部副作用。

每次最多提出三个简短问题。优先说明已经知道什么、还不确定什么。

## 复用与优先级

旧简历是低优先级证据。仅在当前材料没有内容、岗位高度相关或用户明确要求时使用，并保留原始来源；在用户确认前标记为旧材料。

只有用户授权时才保存长期资料。个人档案必须位于 Skill 目录之外，每个新增模块应记录更新日期与来源。

## 作品附件清单

在可获得时记录：

- 原始本地路径与文件名；
- 类型、格式、大小和压缩包内容；
- 基于证据的简短说明；
- 对应项目和目标岗位；
- 建议的专业投递文件名；
- 公开仓库或演示链接；
- 来源显示的账号或组织；
- 学生本人声称的职责及支持材料；
- 核验状态、置信度和最近核验日期；
- 网站上传限制与隐私风险。

不得修改原件。仅在网申需要不同名称、格式、大小或压缩结构时创建投递副本，并记录哪个副本上传到了哪个申请。

连接 GitHub 时，只记录 `github_connector_available: true` 及未来查询所需的公开账号或仓库标识，绝不保存凭据。通过连接或公开网页核验仓库名称和说明。账号归属不能单独证明学生创作了每个仓库或每行代码。
